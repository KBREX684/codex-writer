# Codex Writer v0.7 发布说明

v0.7 的目标是补齐“正式规划 / 正式正文撰写”前必须具备的模型接入边界。

## 新增能力

- 新增 OpenAI-compatible provider，使用 `CODEX_WRITER_OPENAI_COMPATIBLE_*` 环境变量调用 `/chat/completions`。
- 新增 `plan --production`，通过 `planning_agent` 的外部模型路由生成章节任务书 JSON。
- 新增 `write --production`，通过 `draft_agent` 的外部模型路由生成正文草稿，再进入本地审查、抽取、提交和投影流程。
- 新增 `preflight --production`，在正式写作前检查 `planning_agent` / `draft_agent` 是否路由到外部 provider，以及 API、隐私开关是否可用。
- `route-test --provider openai_compatible` 会实际检查 provider 配置和隐私策略。
- `run-agent` 在路由到 `openai_compatible` 时会真实调用 provider，不再只写入“已完成”的占位运行记录。

## 必要配置

```bash
set CODEX_WRITER_ALLOW_EXTERNAL_MODELS=1
set CODEX_WRITER_OPENAI_COMPATIBLE_BASE_URL=https://api.example.com/v1
set CODEX_WRITER_OPENAI_COMPATIBLE_API_KEY=<your-api-key>
set CODEX_WRITER_OPENAI_COMPATIBLE_MODEL=<writer-model>
```

项目路由文件 `.codex-writer/agents/子Agent路由.json` 至少需要：

```json
{
  "routes": {
    "planning_agent": {"provider": "openai_compatible", "model": "writer-model"},
    "draft_agent": {"provider": "openai_compatible", "model": "writer-model"}
  }
}
```

## 行为边界

- 默认 `plan` / `write` 仍保持本地 MVP 行为，便于工程测试和离线演示。
- 只有显式传入 `--production`，才会调用外部模型。
- `--production` 下如果路由仍为 `codex`，返回 `PRODUCTION_PROVIDER_REQUIRED`。
- 外部模型未授权时返回 `PRIVACY_BLOCK`。
- API 配置缺失时返回 `PROVIDER_NOT_CONFIGURED`。
- 模型返回空结果或无效章节任务书 JSON 时返回 provider 级阻断错误。
